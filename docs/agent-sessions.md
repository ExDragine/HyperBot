# QQ 持久会话

同一机器人和用户在私聊中共享一个会话。同一用户在不同群有独立会话，同群成员也各有独立会话。群工作区、群人设和群投递队列仍按群号使用。群管理工具在写入前向 Milky 复核请求者的实时权限。

## 对话轮次

- 通过回复网关的消息成为触发。首轮从当前触发开始，显式引用随当前输入提供。
- 后续轮次以同一用户上一次开始执行的触发与本次触发的数据库主键为边界。区间内的本人发言合入一条模型输入，其他成员近期发言以独立的群聊背景提供。原始 QQ 消息继续逐条保存。
- 历史回读同一会话的近期轮次，包括本人输入和已确认送达的机器人正文。群聊背景只用于当轮。上轮回复晚于当前触发到达时，模型根据送达时间区分回复和当前提问的顺序。
- 普通消息先按事件进入应用的顺序入库，再并行准备转发、引用和媒体。同一用户按入站顺序执行，其他群成员可在前一条慢请求准备期间执行。每个机器人在同一群最多保留 16 个准备、排队或执行中的请求，每人最多 4 个。超额消息保存原始记录，暂不启动回复。门控拒绝及超时会释放对应占位。
- 当轮媒体、显式引用和附件通过原有模型输入路径。历史轮次保留文本与附件引用，需要原文件时可调用聊天历史和附件工具。

## 撤回、成员变化与取消

- 群消息撤回按机器人、群号和消息序号记录。入站去重仍可识别该消息，读取历史、引用、搜索和准备新轮次时会过滤正文及引用快照，已索引的附件路径也会停止向 QQ Agent 开放。通知先到时，迟到的原消息同样受撤回状态约束。
- 撤回待处理的触发会取消该轮。运行中的群轮次也会停止，避免继续使用可能已读入的原文。单轮压缩产生的历史保存在该轮临时状态。
- 成员退群或被踢会停止其待处理轮次。机器人失去群访问权或群解散时停掉该群的待处理轮次。重入后可以续接之前的个人历史，新增上下文从重新入群后开始读取。
- 引用自己的触发消息发送 `/cancel`，或发送 `/cancel <消息序号>`，可以停止该条待处理请求。已送达的输出和已经生效的工具操作由 QQ 平台保留。

## 持久化与恢复

两个新表记录会话归属、原始触发消息、轮次状态和已确认回复。图按轮执行，模型工具调用和临时图状态只保存在当轮。

原始消息和待决策状态一起提交。同一平台消息在入队前因进程中断而重投时，可以继续处理，入队时原子关闭该入口记录。新轮次依次记录排队、执行和投递。明确送达的文本与轮次结算在同一个 SQLite 事务提交，媒体部分失败时也保留已经送达的文本。重启时结束排队和执行中的轮次，正在投递的轮次标为结果不明。连接超时或缺少回执时结束当轮。平台明确拒绝文本时仍可尝试图片回退。

新版从部署后的首次触发建档。升级时从 `env.toml` 删除旧的 checkpoint 配置项，或删除整个 `[sessions]` 段以使用默认值。现有 QQ 原始消息继续用于引用、搜索和群聊记录。

## 预算与观测

```toml
[sessions]
history_max_tokens = 32000
history_window_fraction = 0.25
```

`[storage].query_message_numbers` 限制每次读取的历史轮次数，并分别限制本人补充和群聊背景的候选消息数。历史 token 同时受绝对上限及模型输入窗口比例限制，已知窗口还预留当前输入、系统提示、工具声明与响应空间。模型目录外的窗口使用 8000 token 的上限。本轮的补充和群聊背景另有大小上限。

Dashboard 的 **QQ 会话** 显示已开始及续接轮数、平均排队时间、平均读取上下文大小、失败和投递结果不明次数。这些指标按进程累计。轮次记录保存在 SQLite 中。
